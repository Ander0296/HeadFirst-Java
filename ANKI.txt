¿Qué camino recorre un programa Java desde el archivo fuente hasta ejecutarse?	Se escribe el código en un archivo .java, el compilador javac lo traduce a bytecode (archivo .class), y la JVM (máquina virtual de Java) ejecuta ese bytecode. El bytecode es el mismo para todos los sistemas; lo que cambia es la JVM de cada plataforma.
¿Por qué Java cumple "write once, run anywhere" (escribí una vez, corré en cualquier parte)?	Porque el compilador no genera código de máquina para un procesador concreto sino bytecode neutro, y cada sistema operativo tiene su propia JVM que sabe ejecutar ese mismo bytecode sin recompilar el programa.
¿Cuál es la estructura mínima de una clase ejecutable en Java?	public class MiClase { public static void main(String[] args) { } } — todo el código vive dentro de una clase, la ejecución arranca en main, y el archivo debe llamarse igual que la clase pública: MiClase.java.
¿Por qué el método main es obligatorio y cuál es su firma exacta?	Es el punto de entrada: la JVM busca exactamente public static void main(String[] args) y ejecuta sus sentencias en orden. Sin main, la clase compila pero no se puede ejecutar como programa.
¿Cuáles son las tres cosas que se hacen dentro de un método en Java?	Statements (sentencias que hacen algo y terminan en punto y coma), loops (bucles como while que repiten un bloque), y branching (ramificaciones con if/else que eligen un camino según una condición).
¿Cómo funciona un bucle while en Java?	while (condición) { } repite el bloque mientras la condición boolean sea true. La condición se evalúa ANTES de cada vuelta: si ya empieza en false, el bloque no se ejecuta ni una vez.
¿Cómo funciona if / else en Java y de qué tipo debe ser la condición?	if (condición) { } ejecuta su bloque solo si la condición es true; else { } captura el caso contrario. La condición debe ser un boolean (en Java no vale un número como en otros lenguajes) y va siempre entre paréntesis.
¿Cómo se declara un array en Java y cómo se accede a sus elementos?	int[] numeros = new int[4]; crea un array de 4 posiciones. Se accede con corchetes empezando en cero: numeros[0] es el primero y numeros[numeros.length - 1] el último. Salirse del rango lanza una excepción en ejecución.
¿Cómo se genera un número entero al azar con java.util.Random?	Se importa con import java.util.Random; se crea el generador con Random r = new Random(); y r.nextInt(5) devuelve un entero entre 0 y 4: el límite que le pasás es exclusivo.
¿Qué diferencia hay entre System.out.println() y System.out.print()?	Ambos imprimen en consola, pero println() agrega un salto de línea al final y print() deja el cursor en la misma línea, así lo siguiente que imprimas continúa a continuación.
¿Cuál es el ciclo de trabajo para probar un programa Java desde la terminal?	Guardar el archivo fuente (MiClase.java), compilar con javac MiClase.java (genera MiClase.class con el bytecode), y ejecutar con java MiClase — sin extensión, porque le pasás el nombre de la clase, no del archivo.
¿Qué dos reglas estructurales tiene que cumplir un archivo Java para compilar, más allá de que la sintaxis interna esté bien?	Todo método tiene que estar declarado dentro de una clase, y toda instrucción, bucle o if tiene que estar dentro de un método: ninguno de los dos puede aparecer suelto ni ir directo en el archivo o en el cuerpo de la clase.
¿Qué pasa si escribís un método como public static void main sin encerrarlo dentro de una clase?	El archivo no compila. En Java no existen métodos ni funciones sueltas: todo método tiene que vivir dentro de la declaración de una clase, con la forma class NombreClase { }.
¿Qué pasa si escribís un while o un if directamente en el cuerpo de una clase, sin ponerlo dentro de un método?	Tampoco compila. El cuerpo de una clase solo admite declaraciones (variables, métodos, otras clases); las instrucciones ejecutables como while o if necesitan estar dentro del cuerpo de un método.
¿Cómo se traza (rastrea) a mano un bucle while con varias variables para predecir qué imprime un programa?	Se anota el valor de cada variable justo antes de entrar al bucle, y se lo actualiza línea por línea en cada vuelta, aplicando cada instrucción y cada if en el orden exacto del código — nunca se adivina el resultado sin pasar por cada vuelta una por una.
¿Qué imprime System.out.print(x + "" + y + " ") si x vale 4 e y vale 10 (ambos int)?	Imprime el texto "410 ": los enteros se convierten a texto y se pegan uno al lado del otro sin espacio entre ellos (el espacio final es literal, viene del " " del final). No es una suma: 4 + 10 daría 14, un resultado totalmente distinto.
¿Qué imprime System.out.println(1 + 2 + "3") en Java, y por qué no da lo mismo que System.out.println("1" + 2 + 3)?	El primero imprime "33": como 1 y 2 son ambos int, Java los suma primero (da 3) y recién después concatena con el String "3". El segundo imprime "123": al arrancar con un String, todos los + que siguen concatenan como texto en vez de sumar. El orden de los operandos cambia todo.
¿Por qué conviene usar print() en vez de println() cuando querés armar una palabra o frase juntando varios fragmentos de texto?	Porque print() no salta de línea: cada System.out.print() sucesivo se pega justo después del anterior, en la misma línea. Con println() cada fragmento quedaría en su propia línea, rompiendo la palabra que se quiere armar.
¿Qué pasa si un while nunca modifica la variable que usa su condición, por ejemplo while (x < 10) sin ningún x = x + 1 adentro?	El programa compila y corre sin errores, pero la condición nunca se vuelve false: queda en un bucle infinito, corriendo para siempre sin terminar.
¿Puede el código de un while o un if estar escrito directamente dentro de una clase, sin ponerlo dentro de un método?	No. Todo bucle o condicional necesita vivir dentro de un método; si queda suelto en el cuerpo de la clase, el programa no compila.
Al trazar un while con varios if seguidos (no if/else encadenados) dentro del bucle, ¿cuántos de esos if se pueden disparar en la misma vuelta?	Todos los que cumplan su condición. Al ser if independientes entre sí (no un if/else donde solo uno gana), cada uno se evalúa por separado, así que más de uno puede ejecutarse en la misma vuelta del bucle.
En el enfoque PROCEDURAL de programar, ¿en qué se piensa primero al diseñar un programa?	En los PROCEDIMIENTOS: qué acciones o funciones tiene que hacer el programa (por ejemplo rotate(), playSound()), sin partir de qué "cosas" del problema están involucradas.
En el enfoque ORIENTADO A OBJETOS (OO) de programar, ¿en qué se piensa primero al diseñar un programa?	En las COSAS (objetos) que existen en el problema (por ejemplo Square, Circle, Triangle), dándole a CADA UNA su propio comportamiento, en vez de una función genérica que decide qué hacer según un dato recibido.
Dos programadores reciben la misma consigna: varias formas geométricas que deben rotar y reproducir un sonido propio. Uno usa un enfoque procedural y el otro orientado a objetos. ¿Cómo resuelve cada uno el problema?	El procedural escribe un solo procedimiento genérico rotate(shapeNum) que recibe un número identificando la forma. El orientado a objetos escribe una clase por cada forma (Square, Circle, Triangle), cada una con su propio método rotate() que sabe rotar exactamente esa forma.
¿Qué es una "spec" (specification) en desarrollo de software?	El documento que describe QUÉ tiene que hacer el programa (el comportamiento esperado desde afuera), sin decir CÓMO programarlo por dentro.
Siguiendo el caso anterior, la consigna cambia: se agrega una forma nueva que necesita rotar de manera distinta a las demás. ¿Qué tuvo que hacer cada programador (procedural vs. orientado a objetos) para adaptarse a ese cambio?	El orientado a objetos solo modificó el método rotate() DENTRO de la clase nueva, sin tocar el código ya probado de las otras formas. El procedural tuvo que agregar parámetros nuevos a su procedimiento compartido rotate(), lo que afectó y rompió código que antes funcionaba, obligándolo a testear todo de nuevo.
¿Qué significa que el comportamiento y los datos de un objeto estén "encapsulados" dentro de su propia clase?	Que viven juntos y aislados dentro de esa clase: un cambio ahí adentro no obliga a tocar ni volver a probar el código de las demás clases del programa, a diferencia de un procedimiento genérico compartido por todos los casos.
¿Qué es un "attribute" (atributo) de una clase en POO?	Un dato propio que va a tener CADA objeto de esa clase (por ejemplo, la posición desde la que un objeto debe rotar) — es el nombre informal de lo que formalmente se llama "instance variable" (variable de instancia).
En POO, ¿qué es la HERENCIA (inheritance) entre clases?	Una relación donde una clase (subclase) hereda automáticamente los métodos y atributos de otra clase más general (superclase), sin tener que volver a escribirlos.
¿Qué es una SUPERCLASE (superclass) y qué es una SUBCLASE (subclass)?	La superclase es la clase más general/abstracta que define comportamiento común (ej. Shape con rotate() y playSound()). Las subclases son las clases más específicas que heredan ese comportamiento (ej. Square, Circle, Triangle, Amoeba heredan de Shape).
¿Qué significa hacer OVERRIDE (sobrescribir) de un método heredado en Java?	Que una subclase redefine (escribe su propia versión de) un método que heredó de su superclase, cuando necesita cambiar o extender ese comportamiento para su caso particular.
Si una subclase hereda un método pero necesita comportarse distinto a las demás subclases, ¿cómo lo logra, y cómo sabe el programa en tiempo de ejecución cuál versión usar?	La subclase hace OVERRIDE de ese método (lo redefine con su propio código). En tiempo de ejecución (runtime), la JVM decide automáticamente qué versión del método correr según el tipo real del objeto.
¿Qué gana un programa cuando el resto del código solo "invoca" (llama) un método como rotate() sobre un objeto, sin saber CÓMO lo hace por dentro?	Que se puede agregar un tipo de objeto nuevo (una clase nueva) sin tocar el resto del programa: cada objeto nuevo trae su propio comportamiento, y quien lo usa no necesita cambiar nada.
Al diseñar una clase en POO, ¿qué dos categorías básicas de información hay que pensar sobre los objetos que va a crear?	Las cosas que el objeto SABE (sus atributos, su estado) y las cosas que el objeto SABE HACER (sus métodos, su comportamiento).
¿Por qué el código que usa un objeto no necesita saber CÓMO hace ese objeto lo que le piden, solo QUÉ le están pidiendo?	Porque el objeto es responsable de implementar su propio comportamiento (el "cómo") de forma interna y aislada; quien lo usa solo invoca el método (el "qué") y confía en el resultado. Esto permite agregar objetos nuevos sin tocar el resto del programa.
Nombrá dos ventajas prácticas de la Programación Orientada a Objetos frente a la programación procedural, de las que valoran los programadores en su trabajo diario.	No hace falta tocar ni volver a testear código ya probado para agregar una funcionalidad nueva (alcanza con escribir una clase nueva), y los datos junto con los métodos que operan sobre ellos quedan juntos y organizados en una misma clase.
¿Qué es una "instance variable" (variable de instancia) en una clase Java?	Un dato que un objeto SABE sobre sí mismo (su estado); cada objeto de esa clase puede tener un valor distinto para la misma variable.
En POO, ¿qué significa que "instance" es otra forma de decir "object"?	Que un objeto ES una instancia de su clase: "instance" y "object" se usan como sinónimos. Por eso "instance variable" es simplemente "una variable propia de cada objeto".
¿Qué es un método getter y qué es un método setter? Dá un ejemplo.	Un getter LEE el valor de una instance variable (ej. getAlarmTime()) y un setter lo ESCRIBE/cambia (ej. setAlarmTime()). Es común que un objeto tenga un par getter/setter por cada dato importante que maneja.
¿Dónde se diseñan las instance variables y los métodos de un objeto: en el objeto mismo o en otro lugar?	Se diseñan como parte de la CLASE (el plano). Cada objeto creado a partir de esa clase tiene su propia copia de los valores de las instance variables, pero todos comparten las mismas definiciones de métodos.
¿Qué hace la palabra clave `new` en Java?	Crea un objeto nuevo en memoria siguiendo el plano definido por su clase. Se usa así: Tipo variable = new Tipo();
¿Para qué sirve el operador punto (.) en Java?	Da acceso al estado (instance variables) y al comportamiento (methods) de un objeto específico. Ejemplo: d.size accede al dato size del objeto d, y d.bark() llama al método bark() de ese mismo objeto.
¿Qué es una clase "TestDrive" (o clase tester) en Java, y qué convención de nombre sigue?	Una clase separada cuyo único trabajo es crear objetos de otra clase y probar sus métodos y variables desde su método main(). Se nombra NombreDeLaClaseTestDrive, por ejemplo DogTestDrive para probar la clase Dog.
En la instrucción Dog d = new Dog();, ¿qué representa cada parte?	Dog (a la izquierda) es el TIPO de la variable d; new Dog() crea un objeto Dog nuevo siguiendo el plano de esa clase; d es la variable que guarda una referencia a ese objeto recién creado.
Si creás varios objetos de la misma clase en Java (por ejemplo, tres objetos a partir de la misma clase Movie), ¿comparten los mismos valores en sus instance variables?	No. Cada objeto tiene su PROPIA copia de las instance variables definidas en la clase. Asignarle un valor a una instance variable de un objeto (con el operador punto) no afecta para nada a los demás objetos de esa misma clase.
¿Cuáles son los dos usos distintos que puede tener el método main() en una aplicación Java?	1) Probar una clase real desde una clase separada tipo TestDrive: crear objetos y llamar sus methods para verificar que funcionan. 2) Arrancar/lanzar una aplicación Java real: main() crea uno o pocos objetos iniciales y les delega el resto del trabajo.
¿Qué diferencia hay entre un programa donde main() crea y controla directamente TODOS los objetos, y uno donde los objetos se llaman methods entre sí (se "hablan")?	En el primero, un único método main() hace todo el trabajo: crea cada objeto y llama sus methods ahí mismo. En el segundo, más cercano a una aplicación orientada a objetos real, main() solo arranca el proceso creando un objeto inicial, y ese objeto crea y coordina a otros objetos llamando sus methods: el trabajo se reparte entre objetos en vez de concentrarlo en un único método.
Si declarás una instance variable en Java y nunca le asignás un valor explícito, ¿qué valor tiene por defecto?	Depende del tipo. Para tipos primitivos numéricos (int, double, etc.) el default es 0; para boolean es false. Para tipos de referencia (objetos, String) el default es null, porque significa que la variable todavía no apunta a ningún objeto. Nunca queda "vacía" sin valor.
¿Qué es "the heap" en Java y qué pasa con la memoria de un objeto cuando ya nadie lo usa?	El heap es el área de memoria donde viven TODOS los objetos creados con new, sin importar cuándo o dónde se crearon. Cuando la JVM detecta que un objeto ya no puede usarse (nada lo referencia), queda "eligible for garbage collection": el Garbage Collector lo descarta automáticamente y libera ese espacio para reusar. El programador no libera memoria a mano.
¿Por qué se puede llamar Math.random() directamente, sin escribir new Math()?	Porque random() es un método ESTÁTICO: pertenece a la clase Math en sí misma, no a un objeto particular. Los métodos estáticos se llaman directo sobre el nombre de la clase (NombreClase.metodo()), sin necesidad de crear una instancia con new.
¿Qué hace un bucle while(true) y cómo se sale normalmente de él?	while(true) repite su bloque para siempre, porque su condición nunca es false. Se combina con una instrucción break; en algún punto del bloque, que corta el bucle de inmediato apenas se cumple la condición que lo justifica (por ejemplo, que alguien adivinó un número correctamente).
¿Qué hace el operador || (OR, "o") en una condición de Java, por ejemplo if (a || b || c)?	Da true si AL MENOS UNA de las condiciones es true; no hace falta que todas lo sean. Solo da false cuando TODAS las condiciones son false.
¿Por qué se dice que los methods y variables "static" son la EXCEPCIÓN y no la regla en Programación Orientada a Objetos?	Porque representan un caso especial donde a propósito NO hay múltiples instancias/objetos (ej. un method utilitario como Math.random() o una constante como pi). La inmensa mayoría del comportamiento y los datos de un programa POO real siguen viviendo dentro de objetos individuales, no en members estáticos.
¿Cómo se declara una constante verdaderamente "global" en Java, accesible desde cualquier clase y que nunca cambia de valor?	Marcando la variable como public, static y final a la vez. public la hace accesible desde cualquier código, static hace que pertenezca a la clase (no a un objeto), y final impide que su valor cambie una vez asignado.
¿Qué es un archivo JAR (Java ARchive) y para qué sirve?	Es un formato para empaquetar todas las clases compiladas de una aplicación Java en un solo archivo (basado en el formato de compresión pkzip), para no tener que entregar cientos de archivos .class sueltos al usuario final.
Dentro de un archivo JAR, ¿qué es el "manifest" y qué información contiene?	Un archivo de texto simple que indica cuál de las clases empaquetadas en ese JAR es la que contiene el method main() que hay que ejecutar al correr la aplicación.
En un patrón donde una condición booleana dispara una acción (ej. if (flag == true) { accion(); }), ¿por qué suele ser buena práctica resetear esa variable a false después de ejecutar la acción?	Para evitar que la acción se repita en la próxima vuelta o llamada sin que haya vuelto a cumplirse la condición real que la originó. Sin el reset, el flag quedaría en true para siempre y la acción se ejecutaría de nuevo aunque ya no corresponda.
Al compilar una línea como objeto.metodo(), ¿qué verifica el compilador de Java para dejarla pasar?	Que la clase del objeto DECLARE un method con ese nombre (y parámetros compatibles). Si la clase no tiene ese method, el archivo no compila — el error se atrapa en tiempo de compilación, no al ejecutar.
¿Puede un solo archivo .java contener más de una clase? ¿Con qué restricción?	Sí, puede contener varias clases. La restricción: como máximo UNA puede ser public, y esa clase pública debe llamarse exactamente igual que el archivo. Las demás clases del archivo no llevan public.
¿Qué es "código muerto" (dead code) y por qué es una señal de alarma aunque el programa funcione?	Es código que nunca puede ejecutarse (ej. un if cuya condición jamás será verdadera en ese punto del programa). Aunque la salida sea correcta, confunde al lector ("¿esto cuándo corre?") y suele delatar un malentendido sobre el estado del programa; los IDEs y linters lo marcan automáticamente.
En Java, ¿cuál es la diferencia entre un tipo de dato primitivo (como int) y una referencia?	Un primitivo guarda el VALOR real directo en la variable (ej. int x = 5 guarda el 5 mismo). Una referencia no guarda el objeto en sí, sino la DIRECCIÓN de memoria donde vive ese objeto en el heap.
¿Cuáles son los 4 tipos primitivos enteros de Java y cuántos bits ocupa cada uno?	byte (8 bits), short (16 bits), int (32 bits) y long (64 bits). Los cuatro son signed (admiten valores negativos).
¿Cuál es la diferencia de sintaxis entre declarar un char y un String en Java?	Un char usa comillas SIMPLES y guarda un solo carácter, por ejemplo char c = 'f'; Un String usa comillas DOBLES y guarda una secuencia de caracteres, por ejemplo String s = "f";
¿Para qué sirve poner una L al final de un literal como long big = 3456789L;?	Le avisa explícitamente al compilador que ese número es un long y no un int, evitando que lo confunda con un tipo numérico parecido. Lo mismo pasa con la f en un literal float (ej. 32.5f), para que no se confunda con double. Se puede usar mayúscula o minúscula.
En la asignación int z = x;, ¿z queda vinculado a x o copia su valor?	z copia el VALOR que tenía x en ESE momento. Es una copia independiente: si más adelante el valor de x cambia, z no se entera y mantiene el valor que copió.
¿Por qué la línea byte b = x; no compila, si antes se escribió int x = 24; y el 24 entra perfecto en un byte?	Porque el compilador solo mira el TIPO declarado, no el valor. Ve que se intenta meter un int (32 bits) dentro de un byte (8 bits) y rechaza la línea por la POSIBILIDAD de derrame (spillage). El valor 24 recién existe cuando el programa se ejecuta.
¿Por qué byte b = 24; sí compila pero byte b = x; no compila, siendo x un int que vale 24?	Porque 24 es un literal: el compilador lo tiene delante y verifica que entra en el byte. En cambio x es una variable: el compilador solo ve su tipo declarado (int) y no razona sobre el contenido que tendrá al ejecutarse.
¿Cuáles son las 3 formas de asignar un valor a una variable en Java?	Escribir un literal directo (x = 12;), asignar el valor de otra variable (x = y;), o usar una expresión que combine las dos (x = y + 43;).
En Java, ¿declarar una variable y asignarle un valor son el mismo acto?	No, son dos actos separados que se pueden hacer juntos (boolean listo = true;) o en dos pasos: primero declarar (boolean listo;) y después asignar (listo = true;).
¿Con qué caracteres puede empezar el nombre de una clase, un método o una variable en Java?	Con una letra, un guion bajo (_) o un signo de dólar ($). Nunca con un número. Después del primer carácter sí se pueden usar números. Y el nombre no puede ser una palabra reservada del lenguaje.
¿Qué es una palabra reservada (reserved word) en Java?	Una palabra que el compilador ya tiene tomada con un significado propio del lenguaje (public, static, void, class, int, boolean...). No se puede usar como nombre de una variable, un método ni una clase.
¿Se puede usar el nombre de un tipo primitivo como nombre de variable, por ejemplo int int = 5;?	No. Los ocho tipos primitivos (boolean, char, byte, short, int, long, float, double) son palabras reservadas, así que esa línea no compila.
Al asignar entre primitivas de distinto tamaño, ¿en qué dirección acepta el compilador la asignación sin pedir nada extra?	De chico a grande: meter un valor de un tipo más chico en uno más grande (ej. un byte dentro de un int) es seguro y compila. Al revés, de grande a chico, el compilador lo rechaza por la posibilidad de derrame.
¿Qué guarda realmente en Java una variable de referencia a objeto: el objeto o otra cosa?	Guarda una referencia: bits que representan una MANERA de acceder al objeto (parecido a una dirección o puntero que administra la JVM), nunca el objeto en sí. El objeto real vive solo en el heap.
¿Qué analogía usa Head First Java para explicar qué es una variable de referencia a objeto?	La compara con un control remoto: la variable no es el objeto, es lo que usás para apretar botones (invocar métodos) sobre ese objeto.
En una instrucción como miPerro.ladrar();, ¿qué hace el operador punto (.)?	Usa el objeto referenciado por la variable de la izquierda (miPerro) para invocar sobre ese objeto específico el método de la derecha (ladrar()).
En el diagrama de vasos que compara byte, short, int y long por su tamaño en bits, ¿qué tiene de particular el vaso del tipo referencia?	Su tamaño en bits no le importa al programador (lo administra la JVM); en vez de un valor numérico guarda, metafóricamente, un control remoto hacia un objeto que vive en el heap.
En la instrucción Dog myDog = new Dog();, ¿cuál de los 3 pasos reserva memoria en el heap para el objeto?	El paso 2, new Dog(): crea el objeto Dog en el heap. El paso 1 (Dog myDog) solo reserva la variable de referencia; el paso 3 (=) vincula ambas cosas.
¿Por qué Java no permite hacer aritmética sobre una variable de referencia, por ejemplo miReferencia++?	Porque una referencia guarda una dirección de memoria administrada por la JVM; permitir sumarle o restarle valores rompería la seguridad de memoria del lenguaje, algo que sí ocurre con los punteros en C. Java no es C.
¿Todas las referencias de objeto ocupan el mismo tamaño en una misma JVM, sin importar el tipo de objeto al que apuntan?	Sí. Dentro de una misma JVM, todas las referencias pesan igual entre sí; lo que varía en tamaño son los objetos a los que apuntan, no las referencias.
En Dog myDog = new Dog();, ¿qué hace exactamente el operador de asignación =?	Vincula el objeto Dog recién creado en el heap con la variable de referencia myDog: a partir de ese momento, myDog queda programada para referirse a ese objeto puntual.
En Java, ¿qué significa que una variable de referencia valga null?	Que no se refiere a ningún objeto. null es un VALOR válido (la variable existe y ocupa su espacio), pero no controla nada: no hay objeto del otro lado.
¿Qué le pasa a un objeto del heap cuando ya no queda ninguna variable de referencia apuntándole?	Queda inalcanzable para el programa y pasa a ser elegible para el garbage collector (recolector de basura), que en algún momento libera esa memoria.
Si una variable de referencia se declara final en Java, ¿qué se le prohíbe?	Reasignarla: una vez que se le asigna un objeto, no puede volver a apuntar a otro. El objeto en sí sí puede cambiar por dentro; lo fijo es a cuál se refiere.
En Java, si c es una variable de referencia ya asignada, ¿qué hace la línea Book d = c;?	Copia los bits de la referencia c dentro de d. NO crea un objeto nuevo: quedan dos variables distintas refiriéndose al mismo y único objeto del heap.
¿Qué error de ejecución se produce en Java al invocar un método sobre una variable de referencia que vale null?	NullPointerException: no hay objeto que reciba la llamada. Es un error de runtime, no de compilación, y desde Java 14 el mensaje indica qué variable era null.
En Java, si b y c son referencias ya asignadas a objetos distintos, ¿qué pasa al ejecutar c = b;?	c copia los bits de b, pasa a referirse al mismo objeto que b y SUELTA el objeto que controlaba antes. No se crea ni se destruye ningún objeto: solo cambia a cuál se refiere c.
Si una variable de referencia deja de apuntar a un objeto, ¿ese objeto se vuelve automáticamente basura?	No. Solo si esa era la ÚLTIMA referencia que le quedaba. Si otra variable sigue apuntándolo, el objeto continúa alcanzable y el garbage collector no lo toca.
En Java, ¿qué es una referencia activa (active reference)?	Una variable de referencia que efectivamente apunta a un objeto. Una variable que vale null NO es una referencia activa: existe y ocupa su espacio, pero no controla ningún objeto.
En Java, ¿qué es un objeto alcanzable (reachable object) y por qué importa?	Un objeto del heap al que todavía se puede llegar desde al menos una referencia activa. Importa porque el garbage collector no pregunta si el objeto le sirve a alguien: solo pregunta si se puede llegar hasta él.
Si dos variables de referencia distintas apuntan al mismo objeto, ¿cuántas referencias activas y cuántos objetos alcanzables hay?	Dos referencias activas y UN solo objeto alcanzable. Son contadores separados: las referencias activas cuentan variables, los objetos alcanzables cuentan objetos del heap.
En Java, ¿qué es un objeto abandonado (abandoned object)?	Un objeto del heap que perdió su última referencia activa: ningún camino del programa llega hasta él, así que es elegible para el garbage collector y su memoria se va a liberar.
En Java, un arreglo de primitivas como int[] nums, ¿es un objeto o no?	Es un objeto, aunque guarde primitivas. Por eso nums es una variable de referencia y hace falta crear el arreglo en el heap con new: nums = new int[7];
Al crear un arreglo de objetos en Java, por ejemplo Dog[] perros = new Dog[5];, ¿cuántos objetos Dog quedan creados?	Ninguno. Cada casillero guarda solo una referencia (un control remoto) a un Dog, y arranca en null. Hay que crear cada Dog aparte con new y asignarlo a su posición.
¿Qué ventaja da el índice de un arreglo en Java?	Acceso directo (random access): se llega a cualquier elemento por su posición sin recorrer los anteriores, porque el arreglo es una lista ordenada de tamaño fijo.
En Java, si un arreglo tiene 7 elementos, ¿cuáles son sus índices válidos?	Del 0 al 6. El primer elemento siempre es el índice 0 y el último es longitud menos uno, así que nums[7] no existe y al ejecutar lanza ArrayIndexOutOfBoundsException.
¿Qué guarda cada casillero de un arreglo de primitivas frente a uno de objetos en Java?	En un arreglo de primitivas el casillero guarda el valor mismo (un int, por ejemplo). En un arreglo de objetos el casillero guarda solo una referencia al objeto, y arranca valiendo null.
¿Cuáles son los tres pasos para tener un arreglo de objetos usable en Java?	Uno: declarar la variable de referencia, Dog[] pets; dos: crear el arreglo, pets = new Dog[7]; tres: crear cada objeto y asignarlo a su posición, pets[0] = new Dog();
En Java, ¿qué hace la línea int[] nums = {6, 19, 44};?	Declara la variable, crea el arreglo de largo 3 y lo llena, todo en una sola línea. Es el atajo equivalente a declarar, hacer new int[3] y asignar cada posición por separado.
En Java, si un objeto está guardado en un arreglo, ¿cómo se llama a uno de sus métodos?	Con notación de arreglo más el operador punto: myDogs[0].bark();. El objeto dentro del arreglo no tiene nombre propio, así que se lo nombra por su posición; myDogs[0] ocupa el lugar donde iría una variable de referencia común.
¿Por qué myDogs.bark() no compila si myDogs es un arreglo de Dog?	Porque myDogs es la referencia al arreglo (la bandeja), no a un Dog. El método bark() pertenece a Dog, así que hay que apretar el punto sobre un elemento: myDogs[0].bark();
¿Qué pasa si intentás guardar un objeto de otro tipo dentro de un arreglo en Java?	No compila. El compilador chequea en tiempo de compilación que todo lo que entre sea compatible con el tipo declarado del arreglo, así que un Cat nunca puede entrar en un arreglo de Dog.
¿Qué es implicit widening (ensanchamiento implícito) en Java?	Que Java acepta sin cast un valor de tipo más chico donde va uno más grande, por ejemplo un byte dentro de un arreglo de int, porque el valor siempre entra y no se pierde nada. Al revés, de grande a chico, hace falta un cast explícito.
En Java, ¿length de un arreglo es un método o una variable?	Una variable: se escribe sin paréntesis, array.length. Devuelve la cantidad de elementos, así que el último índice válido es length - 1 y la condición del bucle va con < y nunca con <=.
¿Por qué String name = "Bart"; no lleva new si String es un objeto?	Porque Java le da a los String una sintaxis abreviada, como si fueran primitivas, por lo usados que son. Igual name es una variable de referencia que apunta a un objeto String en el heap.
En Java, si dog1 ya apunta a un objeto, ¿qué hace myDogs[2] = dog1;?	Copia la referencia, no crea ningún objeto nuevo. Quedan dos controles remotos apuntando al mismo objeto: cambiarlo por uno se ve por el otro.
¿Qué imprime System.out.println(name + " says Ruff!"); si name es una referencia sin asignar?	Imprime null says Ruff!. Una variable de referencia no asignada vale null, y al concatenarla con un String se imprime literalmente como el texto null, sin lanzar ningún error.
¿Existe en Java un arreglo de primitivas que no sea un objeto?	No. Un arreglo SIEMPRE es un objeto que vive en el heap, incluso si se declaró para guardar primitivas. No existe el arreglo primitivo, solo un arreglo que contiene primitivas.
¿Qué excepción lanza Java al usar el operador punto sobre una variable de referencia que vale null?	NullPointerException. Ejemplo: se creó el arreglo con new Books[3] pero ningún casillero se llenó con new Books(), así que myBooks[0].title = "X"; revienta: hay control remoto, no hay tele.
¿Qué excepción lanza Java al pedir un índice que el arreglo no tiene?	ArrayIndexOutOfBoundsException. Un arreglo de 3 elementos tiene índices 0, 1 y 2; pedir el 3 revienta en ejecución. Por eso la condición del bucle va con < y nunca con <=.
¿Cómo se distingue un error de compilación de uno de ejecución mirando la salida del programa?	Si no se imprimió NADA y no se generó el .class, es de compilación: el programa nunca existió. Si se imprimieron algunas líneas y después vino una excepción, es de ejecución: arrancó y reventó a mitad de camino.
¿En qué consiste un ejercicio "Code Magnets" (Imanes de Código) en Head First Java?	Te dan fragmentos de un programa Java desordenados, como imanes en una heladera, y hay que reordenarlos a mano para armar un programa que compile y produzca la salida pedida; se pueden repetir fragmentos y agregar llaves { } donde falten.
¿Para qué sirve usar un arreglo de enteros como index[] junto con otro arreglo, por ejemplo con islands[index[y]]?	index[] funciona como un mapa de posiciones, no como datos a mostrar: cada valor guardado ahí indica qué casillero de islands[] hay que mostrar en esa vuelta del bucle, así se cambia el orden de recorrido sin tocar islands[].
¿En qué se diferencia un "Pool Puzzle" de un "Code Magnets" en Head First Java?	Code Magnets da el programa entero desordenado para reconstruirlo completo; Pool Puzzle da una clase con huecos en blanco puntuales y un pool de fragmentos para completar solo esos huecos.
En Java, si hq[3] = hq[1]; después hq[3] = null; y después hq[0] = hq[3];, ¿qué queda en hq[0]?	null. La asignación copia el valor que tiene hq[3] en ESE momento (ya en null); no crea un vínculo permanente con hq[1] ni con ningún valor futuro de hq[3].
En Java, si dos casilleros de un arreglo apuntan al mismo objeto y uno se pone en null, ¿qué le pasa al objeto y a la otra referencia?	El objeto sigue vivo mientras exista al menos una referencia que lo apunte. Poner una referencia en null solo apaga ESA referencia; no destruye el objeto ni afecta a las demás que lo sigan apuntando.
En Java, si dentro de un bucle se hace ref = new Contact(); en cada vuelta usando SIEMPRE la misma variable, ¿qué pasa con los objetos de las vueltas anteriores?	Quedan sin ninguna referencia que los apunte, así que pasan a ser candidatos al garbage collector. Al terminar el bucle solo sigue accesible el último objeto creado.
¿Qué ventaja tiene guardar cada objeto nuevo en un arreglo (contacts[x] = new Contact();) en vez de reusar una sola variable de referencia dentro del bucle?	El arreglo mantiene una referencia viva por cada objeto, así que los diez siguen accesibles después del bucle. Con una sola variable reasignada solo queda accesible el último.
En Java, ¿qué ocupa más memoria: el objeto o la variable de referencia que lo apunta?	El objeto. Una variable de referencia ocupa muy poco porque solo guarda cómo llegar al objeto; ahorrar referencias a costa de perder el acceso a los objetos es un mal negocio.
Si unas líneas que llenan un arreglo dan siempre el mismo resultado en todas las vueltas de un bucle, ¿dónde tienen que ir?	Antes del bucle. Adentro va solo lo que debe pasar en cada vuelta; repetir asignaciones constantes multiplica el trabajo sin cambiar el resultado.
En Java, ¿un mismo error en un bucle puede tener más de una corrección válida?	Sí. Para recorrer los índices 0, 1 y 2 sirve tanto empezar en 0 con el incremento al FINAL del cuerpo, como empezar en -1 con el incremento al PRINCIPIO. No se compara la forma sino qué índices termina visitando: si la salida es idéntica, las dos son correctas.
Si en un bucle el incremento de la variable va ANTES de usarla como índice, ¿con qué valor hay que inicializarla?	Con uno menos que el primer índice que se quiere visitar: para arrancar en 0 hay que inicializarla en -1, porque el incremento ya se aplicó cuando la variable se usa por primera vez.
Al arreglar un bucle que recorre un arreglo, ¿qué hay que verificar además de que compile y no sea infinito?	Que visite EXACTAMENTE los índices esperados, ni uno de más ni uno de menos. Un bucle corrido un paso compila igual, y puede reventar con ArrayIndexOutOfBoundsException o dejar casilleros sin llenar.
En Java, ¿qué es el estado (state) de un objeto y qué es su comportamiento (behavior)?	El estado son los valores de sus instance variables (lo que el objeto SABE) y el comportamiento son sus methods (lo que SABE HACER). Cada objeto de la misma clase puede tener valores distintos.
Dos objetos de la misma clase, ¿pueden tener métodos distintos?	No. Toda instancia de una clase tiene EXACTAMENTE los mismos métodos, pero cada uno se comporta distinto según el valor de sus instance variables: mismo código, distintos datos, distinto resultado.
¿Qué significa que el estado afecta al comportamiento y el comportamiento afecta al estado?	Que un método lee las instance variables para decidir qué hacer (un perro de 32 kg ladra distinto que uno de 4 kg) y también puede modificarlas, cambiando el estado del objeto.
Dentro de un método, si se nombra una variable como title sin poner nada delante del punto, ¿a qué se refiere?	A la instance variable title del objeto sobre el que se llamó ese método. El método ya está parado dentro del objeto, así que no hace falta escribir song1.title.
En Java, ¿cuál es la diferencia entre un argumento (argument) y un parámetro (parameter)?	El argumento es el VALOR que pone quien llama al método (el 3 de d.bark(3);). El parámetro es la VARIABLE LOCAL declarada entre los paréntesis del método donde ese valor aterriza (el int numOfBarks de void bark(int numOfBarks)). Quien llama pasa argumentos; el método toma parámetros.
Si un método declara un parámetro, ¿se lo puede llamar sin pasarle nada?	No. Si un método toma un parámetro hay que pasarle un valor sí o sí, y del tipo apropiado. Llamarlo con los paréntesis vacíos, con menos argumentos de los que pide o con un tipo que no corresponde es un error de COMPILACIÓN.
Dentro de un método, ¿se puede modificar el valor de un parámetro?	Sí. El parámetro es una variable local del método: nace cuando el método arranca y muere cuando termina, así que hacerle numOfBarks = numOfBarks - 1 no afecta a quien llamó.
En la declaración de un método, ¿qué es lo que va escrito justo antes de su nombre, como el void de void bark()?	El tipo de retorno (return type): dice qué tipo de valor devuelve el método. void significa vacío, es decir que no devuelve nada. Todo método se declara con un tipo de retorno.
Si un método se declara con un tipo de retorno como int, ¿qué está obligado a hacer?	A devolver sí o sí un valor de ese tipo (o compatible) con return. Devolver otro tipo es error de COMPILACIÓN: lo que decís que vas a devolver, tenés que devolverlo.
En la línea int theSecret = life.giveSecret(); ¿qué dos cosas tienen que coincidir?	El tipo de la variable que recibe (int theSecret) y el tipo de retorno declarado del método giveSecret(). Si no coinciden, no compila.
¿Cómo se declara un método que toma dos parámetros del mismo tipo?	Repitiendo el tipo en cada uno y separándolos con coma: void takeTwo(int x, int y). Escribir void takeTwo(int x, y) es error de compilación.
Cuando se llama a un método con varios argumentos, ¿cómo se decide en qué parámetro cae cada uno?	Por POSICIÓN, no por nombre: el primer argumento aterriza en el primer parámetro, el segundo en el segundo. Si dos parámetros son del mismo tipo y se invierte el orden, compila igual y el resultado sale mal en silencio.
¿Java es pass-by-value o pass-by-reference?	Siempre pass-by-value, es decir pass-by-copy: al método le llega una COPIA del valor, no el original. Modificar el parámetro adentro del método no cambia la variable de quien llamó.
¿Los nombres de las variables que se pasan a un método tienen que coincidir con los nombres de los parámetros?	No. En t.takeTwo(foo, bar) los valores aterrizan en los parámetros x e y; el método no sabe ni le importa cómo se llamaban afuera.
Si un método recibe un objeto como parámetro y modifica uno de sus atributos adentro del método, ¿ese cambio se ve reflejado afuera?	Sí. También se pasa por valor, pero lo que se copia es la referencia (el control remoto); la copia apunta al MISMO objeto en el heap, así que modificar sus atributos SÍ se ve reflejado afuera. Lo que no se refleja es reasignar la variable parámetro a otro objeto distinto.
¿Puede un método devolver más de un valor?	No directamente: un método declara un solo tipo de retorno. Para devolver varios valores se puede declarar el retorno como un arreglo, por ejemplo int[], y meter todos los valores adentro.
Si un método declara return type int, ¿puede hacer return de una variable byte?	Sí, porque byte se promueve implícitamente a int sin perder información (ensanchamiento implícito, de taza chica a taza grande).
Si un método declara return type int, ¿puede hacer return de una variable double?	No compila: ir de double a int es un angostamiento que puede perder los decimales, y eso requiere un cast explícito que no está permitido implícitamente en un return.
¿Java obliga a usar el valor que devuelve un método?	No. Se puede llamar a un método con return type distinto de void y no usar ni guardar el valor devuelto; a veces se lo llama solo por el trabajo que hace adentro.
En Java, ¿cómo se llama por convención el getter y el setter de una instance variable llamada brand?	getBrand() para leer su valor y setBrand(String) para asignarlo. La convención es get/set más el nombre de la variable con la primera letra en mayúscula.
Getter y setter, ¿qué otro nombre más formal reciben en inglés?	Accessor (el getter) y Mutator (el setter).
¿Qué es la encapsulación (encapsulation) en programación orientada a objetos?	El principio de esconder las instance variables de un objeto para que no sean accesibles directo con el operador punto, y obligar a que se lean o modifiquen solo a través de sus métodos getter y setter.
¿Por qué dejar una instance variable expuesta al operador punto (por ejemplo theCat.height = 0;) es peligroso?	Porque cualquier código externo puede asignarle un valor inválido directamente, sin pasar por ninguna validación, y corromper el estado del objeto.
¿Cuál es la regla práctica inicial de encapsulación en Java?	Marcar todas las instance variables como private, y proveer getters y setters public para controlar el acceso a ellas.
Más allá de validar datos, ¿cuál es la razón más fuerte para acceder a una variable por getter y setter en vez de directo?	Que podés cambiar la implementación más adelante sin romperle el código a nadie: quien usa la clase sigue llamando al mismo método aunque adentro cambie todo.
¿Qué puede hacer un método setter con el valor que recibe, además de asignarlo?	Rechazarlo y no hacer nada, lanzar una excepción (throw an Exception) para avisar del error, o corregirlo redondeándolo al valor aceptable más cercano.
Si una instance variable es public y mucho código externo la asigna con el operador punto, ¿qué pasa el día que hace falta validarla?	Al hacerla private y agregar un setter, todo ese código externo deja de compilar. Si desde el principio hubiera un setter, el cambio sería invisible para todos.
¿Alcanza con elegir bien el tipo de dato (por ejemplo int) para garantizar que el valor de una instance variable sea válido?	No: int acepta números negativos, y valores como cantidad de baños o velocidad de un avión no pueden ser negativos. Esa regla solo puede vivir dentro del setter.
¿Un método puede leer una instance variable private de su propia clase sin pasar por el getter?	Sí. private restringe el acceso desde AFUERA de la clase; cualquier método declarado dentro de esa misma clase accede a sus variables private directamente.
En Java, ¿dónde se puede usar una llamada a un método que devuelve un int?	En cualquier lugar donde se pueda usar un valor int, porque la llamada se resuelve a su valor de retorno. Por ejemplo: int x = 3 + one.getSize();
¿Cómo se llama a un método de un objeto que está guardado dentro de un arreglo?	Con el operador punto sobre el elemento del arreglo: pets[0].setSize(30); el [0] ocupa el lugar que tendría el nombre de la variable de referencia.
Después de ejecutar Dog[] pets = new Dog[7]; ¿cuántos objetos Dog existen en memoria?	Ninguno. Solo se creó el objeto arreglo, con 7 referencias vacías (null). Cada Dog nace recién al ejecutar pets[0] = new Dog();
¿Qué nivel de acceso tiene un método declarado sin public ni private, como void bark() { }?	El nivel default, también llamado package-private: es visible solo desde las clases que están en el mismo paquete.
Si una instance variable de tipo int nunca recibe un valor explícito, ¿qué valor tiene al crear el objeto?	0. Todo tipo numérico entero recibe 0 como valor por defecto si no se inicializa.
¿Qué valor por defecto recibe una instance variable de tipo boolean si no se inicializa?	false.
¿Qué valor por defecto recibe una instance variable de tipo referencia (por ejemplo String) si no se inicializa?	null: una referencia que no apunta a ningún objeto todavía.
¿Cuál es la diferencia entre una instance variable y una variable local en cuanto a dónde se declaran?	La instance variable se declara dentro de la clase pero fuera de cualquier método; la variable local se declara dentro de un método.
¿Qué pasa si un método intenta usar una variable local antes de haberle asignado un valor?	No compila: el compilador de Java rechaza el programa con un error como variable might not have been initialized.
¿Reciben las variables locales un valor por defecto como las instance variables?	No. Las variables locales deben inicializarse explícitamente antes de usarse; Java no les asigna ningún valor automático.
¿Qué compara siempre el operador == en Java, sin importar si son primitivos o referencias?	Siempre compara el patrón de bits de las dos variables: con primitivos compara el valor, con referencias compara si apuntan al mismo objeto en el heap.
¿Cuándo conviene usar el método equals() en vez de == para comparar dos objetos?	Cuando querés saber si dos objetos distintos son iguales en contenido o significado, aunque sean objetos separados en el heap; por ejemplo, dos String con el mismo texto "Fred".
Si Foo c = a; ¿por qué a == c da true sin que se haya creado ningún objeto nuevo?	Porque la asignación c = a copia la referencia de a, no crea un objeto: a y c terminan apuntando al mismo objeto en el heap.
¿Por qué un parámetro de método nunca produce el error "variable might not have been initialized"?	Porque el compilador exige que quien llama al método pase un argumento para cada parámetro, así que el parámetro siempre queda asignado automáticamente al arrancar el método.
En Java, ¿por qué es legal pasar un short o un byte como argumento a un método que espera un int?	Por el ensanchamiento implícito (implicit widening): Java convierte automáticamente un valor de tipo más chico a uno más grande porque no se pierde información, igual que al meter un byte en un arreglo de int.
¿Por qué NO es legal pasar directamente un long como argumento a un método que espera un int, sin conversión explícita?	Porque sería ir de un tipo más grande a uno más chico (narrowing), lo que puede perder información; Java exige un cast explícito para permitirlo.
¿Qué pasa si un método está declarado void pero su cuerpo tiene una sentencia return valor;?	No compila: un método void no puede devolver ningún valor, solo puede usar return; (sin valor) para cortar la ejecución antes de tiempo.
¿Qué diferencia hay entre la condición de un while y la condición de un if que está DENTRO del cuerpo de ese while?	La del while controla cuántas vueltas da el bucle completo; la del if solo decide si, en esa vuelta puntual, se ejecuta el bloque condicional (por ejemplo, sumar un valor extra a un contador).
¿En un ejercicio de completar código con fragmentos de una pileta de opciones (tipo Pool Puzzle), siempre se puede repetir el mismo fragmento en más de un hueco?	No, depende del enunciado: algunos permiten reutilizar un fragmento en varios huecos y otros exigen usar cada fragmento una sola vez; hay que leer la regla antes de resolver.
Si dentro de un bucle tenés count = count + 1; seguido de count = count + metodo(i); donde metodo devuelve 0 o 1 según una condición, ¿qué representa el valor final de count?	La suma de dos cosas: el total de vueltas del bucle (por el +1 fijo en cada una) más la cantidad de vueltas en las que metodo devolvió 1 en vez de 0.
¿Qué tres símbolos usa un diagrama de flujo (flowchart) para diseñar el flujo de un programa antes de escribir código, y qué representa cada uno?	Un círculo representa el inicio o el fin del flujo, un rectángulo representa una acción, y un rombo (diamante) representa un punto de decisión con más de un camino posible.
En el diseño de software, ¿por qué conviene mapear el flujo completo de un programa (con un diagrama de flujo, pseudocódigo u otra herramienta) antes de escribir la primera línea de código?	Porque permite pensar todas las decisiones y acciones necesarias, y detectar huecos o errores de diseño, antes de invertir tiempo escribiendo y corrigiendo código real.
Si un método puede devolver, según el caso, uno de varios strings distintos (por ejemplo "hit", "miss" o "kill"), ¿qué tipo de dato debe declarar como tipo de retorno?	String, porque el tipo de retorno declarado debe poder contener cualquiera de los valores posibles que el método vaya a devolver.
Cuando un programa necesita varias clases, ¿por cuál conviene empezar a programar primero?	Por la clase que NO depende de ninguna otra clase: se la puede construir y probar sola, y recién después se programa la clase que la usa, ya confiando en que la primera funciona.
¿Qué es el prep code (código de preparación) al desarrollar una clase?	Una forma de pseudocódigo enfocada en la LÓGICA de la clase o método, sin preocuparse por la sintaxis; se escribe antes del test code.
¿Qué es el test code al desarrollar una clase, y en qué orden va respecto al prep code y al real code?	Una clase o métodos que prueban el real code y validan que hace lo correcto; se escribe después del prep code y antes del real code.
¿Qué es el real code al desarrollar una clase?	La implementación real de la clase, ya en sintaxis Java de verdad; es el último de los 3 pasos (prep code, test code, real code).
Si una clase A crea y usa una instancia de otra clase B dentro de su main(), ¿por qué a veces no hace falta escribir test code aparte para A?	Porque el propio main() de A, al crear y usar la instancia de B, ya funciona como código de prueba de B; A no necesita un segundo programa que la pruebe a ella misma.
¿Qué es TDD (Test-Driven Development, desarrollo guiado por pruebas)?	Una práctica que consiste en escribir el código de prueba (test code) ANTES de que exista el método que va a probar, para pensar primero qué tiene que hacer ese método.
Si en TDD el test se escribe antes de que el método exista, ¿cómo hace ese test para compilar?	No compila hasta que se escribe un stub (código truncado): una versión mínima del método que compila pero siempre falla (por ejemplo, devolviendo null), solo para que el test pueda ejecutarse.
En TDD, ¿por qué conviene escribir el test antes en vez de esperar a que el código real esté terminado?	Porque el acto de pensar y escribir el test aclara qué tiene que hacer el método; además, apenas se termina de implementar ya se cuenta con un test listo para validarlo, en vez de dejarlo para después (y nunca hacerlo).

En un juego tipo Battleship donde una ficha ocupa unas pocas celdas de una fila más grande, ¿hace falta guardar en el código el estado de TODAS las celdas de la fila?	No: alcanza con guardar en un array las pocas celdas que realmente ocupa la ficha; el resto de la fila es una idea compartida entre el programa y el usuario, pero no necesita existir como estructura de datos.
¿Qué hace en Java el bucle mejorado for (int x : arr) { ... }?	Recorre cada elemento del arreglo arr uno por uno, asignándolo a la variable x en cada vuelta; no usa índice ni condición manual (existe desde Java 5).
¿Qué significa el operador ++ en Java, como en contador++;?	Es el operador de post-incremento: suma 1 al valor actual de la variable; equivale a contador = contador + 1.
¿Qué operador de Java resta 1 a una variable, análogo a ++?	El operador -- (doble guion), por ejemplo contador--; resta 1 al valor actual de la variable.
¿Qué hace la instrucción break dentro de un bucle en Java?	Corta la ejecución del bucle de inmediato, sin evaluar la condición ni recorrer las vueltas que faltan.
¿Por qué conviene escribir el prep code de una clase completa (no solo de un método) antes de tocar la sintaxis real de Java?	Porque permite planificar toda la lógica del flujo (qué declarar, qué repetir, qué condiciones) sin trabarse todavía con errores de sintaxis, dejando la implementación real como el último paso.
¿Qué diferencia real de flujo hay entre cortar un bucle while con break y cortarlo con una bandera booleana (por ejemplo isAlive = false)?	break sale del bucle en el instante exacto en que se ejecuta; la bandera booleana recién corta el bucle en la próxima evaluación de su condición, así que cualquier código que siga después de apagarla, pero dentro del mismo bucle, todavía se ejecuta en esa vuelta.
Según el "Metacognitive Tip" de Head First Java, ¿por qué conviene alternar de tema de estudio cada cierto tiempo?	Porque trabajar un solo lado del cerebro (lógico o creativo) por más de 30 minutos seguidos lo cansa igual que usar un solo brazo; alternar le da descanso y recuperación al otro lado.
¿Qué rango de valores puede devolver Math.random()?	Un double aleatorio entre 0.0 (inclusive) y 1.0 (exclusive): nunca llega a devolver exactamente 1.0.
¿Por qué (int) (Math.random() * 5) da como resultado un entero entre 0 y 4?	Math.random() * 5 da un double entre 0.0 y 4.999..., y el cast (int) trunca la parte decimal sin redondear, dejando siempre un entero de 0 a 4.
Según Head First Java, ¿qué alternativa moderna a Math.random() evita tener que hacer un cast a int?	java.util.Random y su método nextInt(int bound), que devuelve directamente un int aleatorio sin necesitar conversión de tipo.
¿Qué es una helper class (clase auxiliar) en un programa Java?	Una clase que agrupa código de apoyo (por ejemplo, leer datos ingresados por el usuario) para que la clase principal del programa no se mezcle con esa lógica secundaria.
En un método como getUserInput(String mensaje), ¿qué hace normalmente el parámetro String?	Sirve como el texto que se muestra en pantalla para pedirle un dato al usuario antes de leer lo que escribe.

En Java, ¿cuál es la diferencia entre ++x (pre-incremento) y x++ (post-incremento) cuando forman parte de una expresión más grande?	++x incrementa la variable primero y usa ese valor nuevo en la expresión; x++ usa el valor actual de la variable en la expresión y recién después la incrementa. El valor final de la variable es el mismo en ambos casos, pero el valor usado en la expresión difiere.
¿Qué hace el enhanced for loop (for-each) de Java, por ejemplo for (String s : arr)?	Recorre cada elemento de un array o colección sin usar un índice manual: en cada vuelta asigna el siguiente elemento a la variable declarada (s) y ejecuta el cuerpo del bucle; termina cuando no quedan más elementos.
¿Por qué convertir (castear) un valor de un tipo primitivo grande (como long) a uno chico (como short) puede dar un resultado inesperado?	Porque el tipo chico tiene menos bits disponibles: si el valor original no entra, los bits sobrantes se cortan silenciosamente en tiempo de ejecución, cambiando el valor. Por eso Java exige un cast explícito para ese tipo de conversión (narrowing/reductora).

¿Cuáles son las 3 partes de un for clásico en Java, separadas por punto y coma?	initialization (se ejecuta una sola vez, al arrancar), boolean test (la condición, se evalúa antes de cada vuelta) e iteration expression (corre al FINAL de cada vuelta).
¿En qué momento exacto de cada vuelta de un for corre la iteration expression (por ejemplo i++)?	Al FINAL de esa vuelta, después de ejecutarse todo el cuerpo del bucle — no al principio.
¿Cuántas veces imprime valores y qué valores imprime este código: for (int i = 0; i < 8; i++) { System.out.println(i); }?	Imprime 8 veces, los valores 0 a 7 (i arranca en 0 y el bucle sigue mientras i < 8).

¿Para qué sirve la clase Scanner en Java?	Envuelve una fuente de datos (por ejemplo, el teclado vía System.in) para poder leer valores tipados con métodos como nextInt() o nextLine().
¿Qué representa System.in en Java?	El flujo de entrada estándar: por defecto, el teclado.
Al pedir un dato por consola con un mensaje antes, ¿por qué conviene usar System.out.print() en vez de println()?	Porque print() no salta de línea, así el cursor queda al lado del mensaje esperando que el usuario tipee la respuesta en la misma línea.
¿Qué es el "Ready-Bake Code" en Head First Java?	Código que el libro pide tipear tal cual, sin haberlo diseñado el lector; su funcionamiento se explica en detalle más adelante.

¿Qué pasa si casteás un valor long que no entra en el rango de un short, por ejemplo 40002 a short?	Los bits que sobran se cortan silenciosamente: el resultado es un número distinto e inesperado (posiblemente negativo), no un error de compilación ni de ejecución.
Al castear un float a int, por ejemplo (int) 3.14f, ¿qué pasa con la parte decimal?	Se descarta completa (trunca), no se redondea: (int) 3.14f da 3, y (int) 3.99f también daría 3.
¿Se puede castear un boolean a otro tipo primitivo en Java, o viceversa?	No, Java no permite ningún tipo de conversión (ni implícita ni con cast explícito) entre boolean y el resto de los tipos primitivos.
¿Qué es el ejercicio "BE the JVM" en Head First Java?	Un ejercicio donde el lector actúa como si fuera la máquina virtual de Java: recibe el código fuente completo de un programa y tiene que predecir exactamente qué imprime en consola al ejecutarse.
¿Qué es el ejercicio "Code Magnets" en Head First Java?	Un ejercicio donde se dan fragmentos de código Java desordenados (como imanes de heladera) y hay que reordenarlos para armar un programa que compile y produzca una salida exacta dada.
Dentro de un for que recorre un rango de enteros, ¿cómo se puede saltear (skip) un valor puntual del contador sin cambiar el rango del bucle?	Con un if que detecte ese valor puntual y le sume 1 al contador manualmente adentro (por ejemplo if (i == 2) { i++; }), forzando un incremento extra además del que ya hace el for en cada vuelta.
En Java, si hay un break adentro del bucle MÁS INTERNO de dos for anidados, ¿qué bucle corta exactamente?	Solo el bucle interno (el que contiene directamente al break). El bucle externo no se ve afectado: termina esa vuelta del interno y sigue con su propia siguiente vuelta con normalidad.
¿Qué es la sección "Exercise Solutions" (o "Puzzle Solutions") al final de un capítulo de Head First Java?	Un bloque que junta las soluciones oficiales de todos los ejercicios de ese capítulo (Code Magnets, BE the JVM, crucigramas, Mixed Messages, etc.), para que el lector confirme si resolvió bien cada uno.
¿Qué es la Java API?	La biblioteca de clases predefinidas que trae el JDK: miles de clases ya construidas y listas para usar (como ArrayList, String o Math), para no reinventar la rueda en cada programa nuevo.
En un juego que usa un arreglo de instancia con las celdas ocupadas por un objeto, ¿por qué adivinar tres veces la MISMA celda puede dar "hundido" (kill) sin haber acertado las otras celdas?	Porque el método que verifica el acierto suma un hit cada vez que la celda coincide, sin comprobar si esa celda ya había sido acertada antes; repetir la misma celda alcanza igual el total de aciertos necesario.
¿Cómo se puede corregir un método que cuenta como acierto nuevo una celda que el usuario ya había acertado antes?	Usando un segundo arreglo (arreglo paralelo) que guarde qué celdas ya fueron acertadas, y revisándolo antes de sumar un nuevo hit, para no contar dos veces la misma celda.
En Java, ¿se puede cambiar el tamaño de un arreglo (array) después de crearlo?	No. El tamaño de un arreglo queda fijo en el momento de crearlo. Para tener uno más grande o más chico hay que crear un arreglo NUEVO del tamaño deseado, copiarle los elementos que se quieren conservar y reasignar la referencia al arreglo nuevo.
¿Qué es un ArrayList en Java?	Una clase de la biblioteca estándar (Java API) que guarda una lista de objetos y, a diferencia de un arreglo, crece y se achica sola a medida que se agregan o quitan elementos.
En un ArrayList de Java, ¿qué hace el método contains(Object o)?	Devuelve true si la lista contiene ese elemento y false si no. Permite preguntar directamente si algo está adentro, sin recorrer la lista posición por posición buscándolo.
En un ArrayList de Java, ¿para qué sirven los métodos size() e isEmpty()?	size() devuelve la cantidad de elementos que hay actualmente en la lista; isEmpty() devuelve true si la lista no tiene ningún elemento. Como la lista cambia de tamaño, size() puede dar distinto en cada momento.
En un ArrayList de Java, ¿qué diferencia hay entre remove(int index) y remove(Object o)?	remove(int index) quita el elemento que está en esa posición numérica; remove(Object o) busca ese objeto en la lista y quita su primera aparición, sin necesidad de saber en qué posición estaba.
En Java, ¿cómo se pide la cantidad de elementos de un arreglo y cómo se pide la de un ArrayList?	En un arreglo es length, una VARIABLE (sin paréntesis) que indica cuántas posiciones tiene, estén ocupadas o no. En un ArrayList es size(), un MÉTODO (con paréntesis) que indica cuántos elementos hay realmente adentro en ese momento.
En Java, al escribir Dog d = dogArray[1]; ¿el objeto se quita del arreglo?	No. Solo se copia la referencia a ese objeto en otra variable: el arreglo sigue apuntando al mismo objeto y la posición sigue ocupada. Un arreglo no tiene forma de quitar un elemento; lo máximo es asignarle null a esa posición.
En Java, ¿por qué un ArrayList no puede guardar tipos primitivos como int directamente?	Porque un ArrayList guarda objetos, y las primitivas no lo son. Se guardan envueltas en su clase envoltorio (int en Integer, double en Double); desde Java 5 ese envolver y desenvolver es automático y se llama autoboxing.
En Java, ¿qué es el operador diamante (diamond operator) y desde qué versión existe?	Son los ángulos vacíos <> del lado derecho de una creación, como new ArrayList<>(). Desde Java 7 evitan repetir el tipo, que ya está declarado a la izquierda: ArrayList<String> lista = new ArrayList<>(); equivale a escribir <String> en ambos lados.
En Java, ¿se le pueden invocar métodos a un arreglo (array)?	No. Aunque un arreglo ES un objeto, no tiene métodos propios para invocar con el operador punto: vive en un mundo aparte con sintaxis especial de corchetes. Lo único accesible es su única instance variable, length, que por ser variable se escribe sin paréntesis.
En Java, ¿qué pasa si se asigna un valor a un índice que está fuera de los límites de un arreglo?	Compila sin problema, pero revienta en tiempo de ejecución con ArrayIndexOutOfBoundsException. El compilador no puede saber qué índice se va a usar realmente; el chequeo de límites ocurre mientras el programa corre.
En Java, ¿qué es un tipo parametrizado como el <String> de ArrayList<String>?	Es un parámetro de tipo: le dice al compilador que esa lista solo puede guardar objetos de ese tipo. ArrayList<String> se lee como una lista de Strings, y ArrayList<Dog> como una lista de Dogs. Existen desde Java 5.
Al comparar dentro de un bucle en Java, ¿por qué conviene escribir b.equals(item) en lugar de item.equals(b)?	Porque si item vale null, item.equals(b) lanza NullPointerException. Poniendo primero la variable que con seguridad no es null, la comparación simplemente devuelve false en vez de romper el programa.
En Java, ¿qué diferencia hay entre un arreglo y un ArrayList en cuanto al tamaño al crearlos?	new String[2] EXIGE declarar el tamaño en el momento de crearlo, y ese tamaño ya no se puede cambiar. new ArrayList<String>() no pide ningún tamaño: la lista crece y se achica sola a medida que se agregan o quitan elementos.
En Java, ¿qué devuelve el método indexOf() de un ArrayList cuando el elemento buscado no está en la lista?	Devuelve -1. Por eso al usarlo se pregunta si el resultado es mayor o igual a cero (index >= 0) para saber si lo encontró. Preguntar por distinto de cero sería un error, porque el índice 0 es una posición perfectamente válida.
En Java, ¿qué hace el método isEmpty() de un ArrayList?	Devuelve un boolean: true si la lista no tiene ningún elemento y false si tiene al menos uno. Equivale a preguntar size() == 0, pero se lee mucho mejor.
En Java, ¿qué diferencia hay entre invocar remove() sobre un ArrayList y asignar null a una posición de un arreglo?	remove() saca el elemento de verdad y la lista se achica: size() pasa a devolver uno menos. Asignarle null a una posición de un arreglo deja esa posición ahí ocupando lugar, y length sigue devolviendo lo mismo.
Al programar, ¿por qué es riesgoso llevar un contador aparte para saber en qué estado está una colección?	Porque hay que mantenerlo sincronizado a mano y cualquier olvido produce un bug silencioso. Si la colección puede representar el estado sola (por ejemplo quitando el elemento acertado y preguntando si quedó vacía), conviene dejar que lo haga ella.
¿Por qué conviene sacar la lógica del método main y ponerla en métodos de instancia de un objeto?	Porque main es solo la puerta de entrada del programa: su trabajo es crear un objeto y pedirle que arranque. Si la lógica vive dentro de main no se puede reutilizar ni probar por partes, y el método crece sin control.
En programación orientada a objetos, ¿qué significa que un objeto delegue trabajo en otro?	Que en vez de hacer la tarea él mismo, le pide a otro objeto especializado que la haga y usa el resultado. Así cada clase sabe hacer una sola cosa, el código queda más corto y cambiar una parte no rompe las demás.
Al contar los objetos que crea un programa, ¿alcanza con contar las clases que se escribieron?	No. Una sola clase puede producir muchos objetos: si el programa crea tres objetos de la misma clase y cada uno crea internamente su propia lista, ya hay siete objetos en memoria contando la lista que los agrupa, salidos de solo dos o tres clases.
Cuando un objeto guarda a otro en una de sus instance variables, ¿qué relación hay entre los dos?	Es una relación TIENE-UN (has-a), también llamada composición. El objeto contenedor guarda una referencia al otro y le puede pedir cosas invocando sus métodos con el operador punto.
En Java, ¿por qué se comparan dos Strings con .equals() y no con ==?	Porque == pregunta si las dos referencias apuntan al MISMO objeto en memoria, mientras que .equals() compara el contenido, o sea si dicen lo mismo. Para texto casi siempre se quiere lo segundo: if (result.equals("hit")).
¿Qué gana un programa al declarar private los métodos internos de una clase y dejar public solo la puerta de entrada?	Encapsulamiento: nadie de afuera puede invocar un paso interno fuera de orden y dejar el objeto en un estado roto. La clase expone qué se le puede pedir y esconde cómo lo hace, así se puede cambiar por dentro sin romper a nadie.
¿Qué pasa si se quita un elemento de una lista con remove() mientras se la recorre con un for mejorado (enhanced for)?	Java lanza ConcurrentModificationException en tiempo de ejecución. Solo es seguro si inmediatamente después se corta el bucle con break, porque entonces no hay una vuelta siguiente. La forma robusta es usar un Iterator con su propio remove(), o removeIf().
¿Por qué conviene inicializar una variable de resultado con el caso pesimista, por ejemplo String result = "miss";?	Porque si nadie la cambia queda el valor por defecto correcto, y así no hace falta un else que cubra el caso "no pasó nada". Menos ramas, menos lugares donde equivocarse.
¿Qué es un magic number y por qué se evita?	Es un valor literal suelto en medio del código, como if (numOfGuesses <= 18), sin nada que explique de dónde salió. Se reemplaza por una constante con nombre, por ejemplo private static final int GOOD_SCORE = 18;, que se lee sola y se cambia en un solo lugar.
